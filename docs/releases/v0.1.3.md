# CorpusOne 0.1.3 beta

Cette préversion ajoute quatre optimisations/alertes de transparence
appliquées lors de l'extraction, toutes non silencieuses (une note apparaît
systématiquement dans l'en-tête SOURCE du corpus et dans le rapport).

## Points principaux

- **Déduplication des en-têtes/pieds de page répétés (PDF)** : une ligne
  strictement identique en début/fin de page (en-tête, pied de page,
  filigrane) répétée sur au moins 3 pages **et** la moitié des pages d'un
  même PDF n'est conservée qu'une fois. Le corps du texte n'est jamais
  touché — seules les extrémités de page sont candidates.
- **Retrait des images base64 intégrées dans les fichiers Markdown** : un
  `data:image/...;base64,...` collé dans un `.md` (export Obsidian/Notion,
  capture d'écran collée) est remplacé par une note ; en contexte texte, un
  LLM ne peut de toute façon pas « voir » l'image depuis du base64 brut —
  c'était du bruit pur.
- **Détection de doublons de contenu entre fichiers** : deux fichiers
  différents (chemins distincts) dont le texte extrait est strictement
  identique — copie dans deux dossiers, sauvegarde, export dupliqué — ne
  sont comptés/inclus qu'une fois dans le corpus ; le second renvoie vers
  l'original.
- **Alerte non bloquante sur les secrets potentiels** : avant que le
  corpus ne parte vers un chat LLM externe, une détection heuristique
  conservatrice (clé AWS, bloc de clé privée, jeton Slack/JWT, motif
  `api_key=`/`secret_key=`/`access_token=`/`client_secret=`) signale les
  fichiers concernés. Ne bloque jamais, ne modifie jamais le texte, et ne
  rapporte jamais la valeur trouvée — seulement le type de secret et le
  numéro de ligne.
- **Rapport enrichi** : nouvelle section « Notes » dans le rapport MD
  regroupant ces quatre alertes par fichier.

## Choix techniques notables

- Une idée de compression sémantique du texte (retirer des mots jugés « peu
  informatifs » pour le LLM) a été explicitement écartée : elle contredit
  la promesse du CdC (« texte intégral extractible, sans perte silencieuse »)
  et risque de retirer des négations, chiffres ou termes précis dans un
  document juridique ou financier. Seuls des doublons **exacts** (lignes,
  fichiers) sont retirés — jamais une reformulation ou un résumé.
- Aucune nouvelle dépendance : les quatre fonctionnalités n'utilisent que la
  bibliothèque standard (`re`, `hashlib`).
- Détail des seuils et rationale complète : D-062 à D-065 dans
  `docs/journal-decisions.md`.

## Validation

- 278 tests réussis, 39 ignorés (jeu local `tests/samples_real/` non
  versionné) — 22 nouveaux tests couvrant les quatre fonctionnalités.
- `ruff check`, `ruff format --check` et `mypy --strict` validés (aucune
  nouvelle erreur introduite sur les fichiers modifiés).

## Installation Windows

1. Télécharger l'archive ci-dessus (et son `.sha256` pour vérification).
2. Extraire **le seul** `CorpusOne.exe` de l'archive vers un dossier de
   votre choix. Aucun autre fichier n'est requis : le runtime Python est
   embarqué dans l'exe.
3. Lancer `CorpusOne.exe` (double-clic). Aucun droit administrateur et
   aucune connexion réseau ne sont nécessaires.

Le binaire n'est pas signé : Windows SmartScreen peut afficher un
avertissement lors du premier lancement. Vérifiez l'empreinte SHA-256 avant
l'exécution.

## Limites de cette beta

- La détection de secrets est volontairement conservatrice (peu de motifs,
  haute confiance) : elle peut manquer des secrets à un format inhabituel,
  et ne remplace pas une revue manuelle avant de partager un corpus.
- La déduplication de contenu compare le texte **après extraction** (donc
  deux fichiers de formats différents avec le même contenu textuel sont
  aussi détectés), mais pas les fichiers quasi identiques (une seule ligne
  de différence n'est pas un doublon).
- Pas d'OCR : les documents constitués uniquement d'images restent signalés,
  pas reconnus.
