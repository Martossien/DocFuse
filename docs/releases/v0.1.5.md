# CorpusOne 0.1.5 beta

Cette préversion élargit fortement la couverture de formats (EPUB, Word/
Excel/PowerPoint 97-2003 legacy, email Outlook `.msg`), étend l'OCR des
images intégrées à Excel et OpenDocument, et corrige plusieurs bugs trouvés
en testant sur des dossiers réels — dont un cas de réparation d'encodage
qui, en configuration par défaut, aurait silencieusement altéré des
centaines de fichiers non corrompus (corrigé avant publication).

## Points principaux

### Nouveaux formats : EPUB, Word/Excel/PowerPoint legacy, Outlook .msg

- **`.epub`** : texte extrait dans l'ordre de lecture (spine), titre/auteur
  capturés, tableaux/listes convertis en Markdown. Implémentation native
  (aucune nouvelle dépendance) — `ebooklib`, le choix le plus évident, est
  en AGPLv3+, incompatible avec les règles du projet.
- **`.doc` / `.xls` / `.ppt`** (Word/Excel/PowerPoint 97-2003 binaires) via
  `office_oxide` (Rust, MIT/Apache-2.0, ~1,3 Mo/plateforme, aucun binaire
  externe).
- **`.msg`** (email Outlook) via `python-oxmsg` (MIT). Les deux
  bibliothèques ont été testées directement sur des fichiers réels avant
  adoption — voir « Validation » ci-dessous.

### OCR des images intégrées étendu à Excel et OpenDocument

Après DOCX/PPTX en 0.1.4, l'OCR automatique (+ export optionnel avec tag
de position pour description par IA) couvre désormais aussi `.xlsx`
(feuilles) et `.odt`/`.odp`. Même mécanisme, même moteur Tesseract, mêmes
réglages (`--extract-images`).

### Robustesse : mojibake, bombes zip, mot de passe Office

- **Réparation automatique du mojibake** (encodage incohérent) sur les
  fichiers texte/Markdown/CSV/JSON/XML/HTML — jamais silencieuse, tracée en
  en-tête `## SOURCE:`. Configuration délibérément restreinte à la
  détection de corruption réelle : la configuration par défaut de la
  bibliothèque utilisée altérait aussi des guillemets typographiques
  légitimes, des ligatures, des fins de ligne et de la ponctuation chinoise
  correcte — désactivé après l'avoir constaté en testant sur ~1400 fichiers
  réels (détail : `docs/journal-decisions.md`, D-093).
- **Garde-fou "bombe zip"** sur tous les formats conteneurs ZIP (DOCX/
  PPTX/XLSX/ODF/EPUB) avant tout parsing.
- **Fichiers Office protégés par mot de passe à l'ouverture** : donnaient
  une erreur bas niveau incompréhensible, remplacée par un message clair.
- **GUI** : tri des colonnes du tableau de fichiers, fenêtre par défaut
  élargie (boutons du bas qui pouvaient déborder sous Windows).

## Choix techniques notables

- Toutes les nouvelles dépendances (`ftfy`, `office_oxide`, `python-oxmsg`)
  vérifiées MIT/Apache-2.0/BSD sur PyPI avant adoption, jamais sur la seule
  foi d'une description — aucune GPL/AGPL/LGPL.
- `office_oxide` est une extension Rust compilée (binaire natif par
  plateforme) — c'est son tout premier build réel dans un exécutable
  Windows packagé ; en cas de souci de lancement lié à ce format
  spécifiquement, signalez-le (voir « Limites » ci-dessous).
- Détail complet des correctifs et leur rationale : D-089 à D-094 dans
  `docs/journal-decisions.md`.

## Validation

- 471 tests réussis, 39 ignorés (jeu local `tests/samples_real/` non
  versionné).
- `ruff check`, `ruff format --check` et `mypy --strict` validés.
- Testé en conditions réelles sur ~/Documents et ~/Téléchargements (plus de
  1400 fichiers) avec toutes les nouvelles fonctionnalités actives
  simultanément, y compris les nouveaux formats `.doc`/`.xls`/`.msg` sur
  des fichiers réels de l'utilisateur (pas seulement des fixtures
  synthétiques).

## Installation Windows

1. Télécharger l'archive ci-dessus (et son `.sha256` pour vérification) —
   `CorpusOne` pour l'usage standard, `CorpusOne-OCR` si vous voulez l'OCR
   des PDF/images scannés sans installer Tesseract.
2. Extraire **le seul** `.exe` de l'archive vers un dossier de votre choix.
   Aucun autre fichier n'est requis.
3. Lancer l'exe (double-clic). Aucun droit administrateur et aucune
   connexion réseau ne sont nécessaires.

Le binaire n'est pas signé : Windows SmartScreen peut afficher un
avertissement lors du premier lancement. Vérifiez l'empreinte SHA-256 avant
l'exécution.

## Limites de cette beta

- `office_oxide` (`.doc`/`.xls`/`.ppt`) : premier build Windows réel de
  cette dépendance native — signalez tout souci de lancement ou
  d'extraction spécifique à ces trois formats.
- Fenêtre GUI élargie (retour utilisateur v0.1.4) : correctif de bon sens,
  pas confirmé reproduire exactement le bug de débordement de boutons
  signalé — à confirmer.
- `.ods` (position d'image) et OCR des images EML/MHTML : non couverts,
  hors périmètre de cette version.
