# CorpusOne 0.1.2 beta

Cette préversion ajoute deux moteurs de comptage de tokens précis (en plus de
l'approximation générique déjà en place) et automatise la publication du
binaire Windows sur les Releases GitHub.

| **Empreinte SHA-256** de l'archive | [Télécharger .sha256](https://github.com/Martossien/DocFuse/releases/download/v0.1.2/CorpusOne-0.1.2-beta-windows-x64.zip.sha256) |

## Points principaux

- **Moteurs de comptage précis en option** : en plus de l'approximation
  générique (`octets/4`, inchangée par défaut), deux nouveaux moteurs
  calculent le nombre de tokens **réel** — `--tokenizer-engine mistral`
  (tokenizer Tekken de Mistral) ou `--tokenizer-engine openai` (encodage
  `o200k_base`, GPT-4o/4.1/o-série). Disponibles en CLI (`--tokenizer-engine`,
  `--list-tokenizers`), en config JSON (`tokenizer_engine`), et dans la GUI
  (menu « Précision du comptage »). Entièrement locaux, zéro connexion
  réseau. Registre extensible (`core/tokenizers/`) pour d'autres moteurs.
- **GUI : changement de moteur instantané** : basculer le menu recalcule
  immédiatement le tableau et les totaux, sans relancer l'analyse (même
  principe que le recalcul déjà existant pour le plafond de contexte).
- **Rapport enrichi** : le rapport MD/JSON indique désormais quel moteur de
  comptage a été utilisé, avec le détail des tokens par fichier.
- **Publication automatisée** : l'exe Windows est désormais attaché
  automatiquement à chaque Release GitHub publiée (auparavant fait à la main).

## Correctifs

- **GUI** : le tableau de fichiers restait figé sur les chiffres de l'ancien
  moteur de comptage quand on changeait le menu sans relancer l'analyse —
  trouvé en testant la fenêtre réelle, pas seulement les tests automatisés.
- **CI** : l'upload de l'artifact Windows échouait silencieusement depuis le
  passage en mode `--onefile` (chemin resté sur l'ancien dossier
  `--onedir`) — chaque run affichait un avertissement ignoré au lieu de
  publier l'exe. Corrigé, et transformé en échec explicite en cas de
  régression similaire.

## Choix techniques notables

- Nouvelle dépendance : `tiktoken` (MIT). Le paquet `mistral-common` n'a
  **pas** été retenu : une de ses dépendances transitives (`pycountry`) est
  sous licence LGPL-2.1, incompatible avec la politique zéro-copyleft du
  projet une fois figée dans un exécutable onefile. Le moteur Mistral
  reconstruit directement l'encodage Tekken avec `tiktoken` + un fichier de
  vocabulaire vendoré (extrait du dépôt `mistral-common`, Apache-2.0).
- Le moteur OpenAI utilise le fichier de vocabulaire officiel `o200k_base`
  distribué par `tiktoken`, vendoré localement plutôt que téléchargé au
  premier lancement (comportement par défaut de `tiktoken.get_encoding()`).
- Les deux moteurs sont vérifiés par tests de parité contre les
  implémentations de référence (le vrai `Tekkenizer` de `mistral-common`,
  le vrai `tiktoken.get_encoding("o200k_base")`) et par des tests
  garantissant l'absence de tout appel réseau.

## Validation

- 295 tests collectés : **256 réussis**, 39 ignorés (le jeu local
  `tests/samples_real/` n'est pas versionné).
- `ruff check`, `ruff format --check` et `mypy --strict` validés sur 44
  fichiers source.
- Recette fonctionnelle : **7/7 PASS**.
- Testé sur un corpus de documents réels fournis par l'utilisateur (65
  fichiers synthétiques 10 Ko–2 Mo + 14 documents variés DOCX/PDF/MD/HTML/
  PPTX/ODT/RTF/XLSX/CSV) : 0 erreur d'extraction, contenu intact, comptes de
  tokens cohérents et différenciés par moteur sur l'ensemble du corpus.
- Build Windows testé via la CI (`build-windows`) : build PyInstaller
  réussi avec les deux nouveaux vocabulaires embarqués.

## Installation Windows

1. Télécharger l'archive ci-dessus (et son `.sha256` pour vérification).
2. Extraire **le seul** `CorpusOne.exe` de l'archive vers un dossier de
   votre choix (clé USB, dossier utilisateur, partage réseau). Aucun autre
   fichier n'est requis : le runtime Python est embarqué dans l'exe.
3. Lancer `CorpusOne.exe` (double-clic). Aucun droit administrateur et
   aucune connexion réseau ne sont nécessaires.

Le binaire n'est pas signé : Windows SmartScreen peut afficher un
avertissement lors du premier lancement. Vérifiez l'empreinte SHA-256 avant
l'exécution.

## Limites de cette beta

- Pas d'OCR : les documents constitués uniquement d'images sont signalés,
  pas reconnus.
- L'estimation par défaut reste volontairement générique (`octets UTF-8 / 4`,
  marge de 15 % par défaut) ; les moteurs Mistral et OpenAI donnent un
  compte réel pour leurs modèles respectifs uniquement.
- Les tests fondés sur des documents réels (`tests/samples_real/`) restent
  à rendre reproductibles dans un clone frais.
