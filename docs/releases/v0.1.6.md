# CorpusOne 0.1.6 beta

Cette préversion est le résultat d'un **audit complet du code** en quatre
lots — bugs de contenu perdu, encodage, performance, maintenabilité — dont
chaque constat a été reproduit sur un cas concret avant correction, puis
d'un retour d'usage réel : le corpus **PDF** est nettement mieux exploité
que le Markdown par les assistants qui indexent les documents. Chaque page
du PDF indique désormais son fichier source.

## Points principaux

### Corpus PDF : chaque page indique son fichier source

L'en-tête de chaque page porte `Corpus DocFuse — fichier (3/12)` en plus du
numéro de page. Les assistants d'entreprise qui indexent un PDF le
découpent page par page : chaque passage reste ainsi attribuable à sa
source, ce qu'un `.md` découpé à taille fixe ne garantit pas. Le README
gagne une section **« Quel format pour quel outil ? »** : Markdown pour un
LLM qui reçoit le fichier entier, PDF pour un assistant à recherche — avec
la limite honnête qu'un tel assistant ne lit jamais tout le corpus.

### Audit, lot 1 — 23 correctifs « contenu perdu / plantage »

- **Le glisser-déposer n'avait jamais fonctionné** (bibliothèque Tcl
  jamais chargée, erreur avalée) — corrigé et embarqué dans l'exe.
- HTML : titres, tableaux et listes perdus dès que le corps est dans un
  `<div>` ; mots soudés autour du gras et des liens. ODF : sections, cadres
  et index ignorés ; `.ods` sans structure. DOCX : zones de texte en double,
  en-tête répété par section. XLSX : une feuille graphique faisait perdre
  tout le classeur. EML : pièce jointe prise pour le corps, `Cc` absent.
  EPUB : chapitres sautés en silence. XML : déclaration `encoding=` ignorée.
- Retirer l'original d'un doublon dans l'interface faisait disparaître son
  contenu du corpus.
- Plantages entiers évités (PDF avec `<` dans un nom, tri par date sur lien
  cassé, RTF, CSV à long champ, config mal typée) ; erreurs de génération
  affichées dans l'interface au lieu de disparaître.

### Audit, lot 2 — encodage

La réparation de mojibake ne touche plus qu'à la corruption d'encodage
(entités HTML, codes ANSI et texte NFD ne sont plus réécrits) ; un fichier
UTF-8 coupé au milieu d'un caractère n'est plus basculé en cp1252 ; une
page HTML sans charset n'est plus « devinée » en encodage exotique.
Fichiers ASCII : réparation court-circuitée (2,4 s économisées sur
200 000 lignes).

### Audit, lot 3 — vitesse, sortie strictement identique

Chaque gain mesuré, et le corpus généré vérifié **identique octet par
octet** avant/après :

- OCR des images intégrées (DOCX, PPTX, XLSX, ODF) parallélisé à
  l'intérieur d'un fichier : une présentation de 44 images passe de
  **21,0 s à 3,0 s**.
- Processus Tesseract bornés globalement, nombre de workers dérivé du
  processeur : un dossier de 120 fichiers passe de **28,4 s à 10,6 s**.
- XLSX lu une fois par feuille au lieu de sept, DOCX sans re-parse,
  changement de moteur de comptage instantané (cache), saisie du plafond
  sans reconstruction de la table à chaque frappe.

### Audit, lot 4 — maintenabilité

Code dupliqué factorisé, ce qui a révélé trois bugs : un `.md` contenant
des ``` était encapsulé dans des backticks (contraire au CdC), le type d'un
fichier différait dans le rapport selon l'issue de l'extraction, la CLI et
la GUI n'écrivaient pas au même endroit pour un fichier seul. Plus : codes
retour CLI corrigés, bouton « Générer » qui suit le choix PDF, barre de
progression qui ne recule plus, images exportées de documents homonymes
qui ne s'écrasent plus.

## Choix techniques notables

- Aucune nouvelle dépendance. Les corrections et leur rationale sont
  détaillées dans `docs/journal-decisions.md` (D-095 à D-100).
- `Extractor.file_type` disparaît au profit d'une politique unique
  (`file_type_for(path)`) ; `generate_corpus(result, output_path)` perd ses
  paramètres en doublon ; nouveau module `output/paths.py` partagé CLI/GUI.

## Validation

- 534 tests réussis, 39 ignorés (jeu local `tests/samples_real/` non
  versionné) ; `ruff check`, `ruff format --check`, `mypy --strict` validés ;
  CI verte sur Ubuntu et Windows (3.11 à 3.13).
- Testé en conditions réelles sur ~/Documents et ~/Téléchargements
  (1 417 fichiers) avec OCR et export d'images, **en Markdown et en PDF** :
  2 erreurs, toutes deux des JSON réellement corrompus.
- Interface relancée sur un écran réel : glisser-déposer effectivement
  actif, états des boutons cohérents.

## Installation Windows

1. Télécharger l'archive ci-dessus (et son `.sha256` pour vérification) —
   `CorpusOne` pour l'usage standard, `CorpusOne-OCR` si vous voulez l'OCR
   des PDF/images scannés sans installer Tesseract.
2. Extraire **le seul** `.exe` de l'archive vers un dossier de votre choix.
   Aucun autre fichier n'est requis.
3. Lancer l'exe (double-clic). Aucun droit administrateur et aucune
   connexion réseau ne sont nécessaires.

Le binaire n'est pas signé : Windows SmartScreen peut afficher un
avertissement lors du premier lancement. Vérifiez l'empreinte SHA-256 avant
l'exécution.

## Limites de cette beta

- Fenêtre maximisée au démarrage sous Windows (retour v0.1.5 sur les
  boutons du bas masqués) : mitigation de bon sens, non reproduite ici — à
  confirmer sur machine réelle.
- Un assistant qui répond par recherche (RAG) ne lit jamais tout le corpus,
  même en PDF : les comptages et les citations « ligne précédente » restent
  peu fiables de son côté.
- Mise à jour en place des lignes de la table GUI et génération dans un
  thread worker : reportées (voir « Reste à faire » dans `AGENTS.md`).
