# CorpusOne 0.1.4 beta

Cette préversion ajoute deux fonctionnalités majeures — l'inclusion des
fichiers de développement (codebases) et l'OCR des PDF scannés — et corrige
**26 bugs**, dont un crash critique du processus (SIGSEGV) et 17 cas de
perte silencieuse de contenu trouvés par un audit systématique de chaque
extracteur, vérifié sur des fichiers réels.

## Points principaux

### Fichiers de développement traités comme texte brut

Une soixantaine d'extensions courantes (`.py`, `.js`/`.ts`, `.vba`, `.sh`,
`.ps1`, `.sql`, `.css`, `.java`, `.c`/`.cpp`, `.go`, `.rs`, `.toml`, etc. —
liste complète : `constants.CODE_EXTENSIONS`) sont désormais incluses dans
le corpus au lieu d'être ignorées silencieusement — cas d'usage LLM
fréquent (envoyer une codebase). Les bundles tiers minifiés (`*.min.js`,
`*.min.css`) et les dossiers `node_modules/`, `vendor/`, `dist/`, `build/`
sont explicitement exclus (trouvé en testant : sur un dossier réel, ce
bruit représentait 91 % du corpus généré).

### OCR des PDF scannés (portée v1 : PDF uniquement)

Un PDF scanné était détecté (alerte « peu de texte ») mais son contenu
n'était jamais récupéré. Chaque page est désormais classée (texte natif
suffisant / à OCRiser / vide / mixte) à partir du texte déjà extrait par
pdfminer, et les pages qui en ont besoin sont reconnues via Tesseract, si
disponible. Jamais bloquant : sans Tesseract, le comportement reste
strictement identique à avant, avec une note expliquant pourquoi.

## Corrections — 26 bugs, deux vagues d'audit sur les extracteurs

Chaque correctif a un test de non-régression construit avec la
bibliothèque réelle du format (jamais un mock), reproduisant la structure
exacte du bug avant de vérifier le correctif.

**Critique** :

- **Crash du processus entier (SIGSEGV)** lors de l'OCR de plusieurs PDF en
  parallèle — PDFium (`pypdfium2`) n'est pas thread-safe entre documents
  distincts chargés depuis des threads différents. Trouvé en testant sur un
  vrai dossier de 741 fichiers. Corrigé par un verrou global.

**Perte silencieuse de contenu** (forte gravité, D-069 à D-076) :

- **PDF** : texte imbriqué dans un Form XObject (`LTFigure`, ex. TCPDF)
  ignoré — jusqu'à ~2500 caractères/page perdus ; mot de passe utilisateur
  vide rejeté comme fichier illisible.
- **DOCX** : texte en suivi des modifications (`w:ins`) et contrôles de
  contenu Word (`w:sdt`) invisibles.
- **EML** : email transféré en pièce jointe (`message/rfc822`) — sujet et
  corps totalement perdus.
- **ODF (.odt)** : en-têtes/pieds de page (`styles.xml`) jamais lus.
- **HTML** : `<meta charset>` jamais consulté → charabia total pour tout
  encodage legacy non latin (cyrillique, etc.).
- **PPTX** : formes groupées — texte/tableaux dans un groupe invisibles.
- **RTF** : texte de repli des objets OLE incrustés perdu.
- **XLSX** : formules jamais calculées → cellule vide sans trace.

**Qualité/gravité moyenne** (D-080 à D-087) :

- **DOCX** : zones de texte — bug de casse XML qui les empêchait de
  **jamais** fonctionner, sur aucun fichier, depuis leur introduction ;
  celles des en-têtes/pieds de page ; tableau imbriqué dans une cellule.
- **XLSX** : dimension de feuille mal déclarée → troncature silencieuse ;
  cellules fusionnées non propagées aux autres cellules de la plage.
- **PDF** : texte poubelle `(cid:...)` laissé tel quel si OCR indisponible.
- **ODF (.odp)** : notes d'orateur mélangées au contenu visible des diapos.
- **HTML** : commentaires qui fuitaient dans le texte extrait.
- **MHTML** : `alt` des images jamais extrait.

## Choix techniques notables

- `ruff` épinglé sur une version exacte (`==0.16.5`) — la dérive local/CI
  avait cassé la publication initiale de la v0.1.3.
- OCR : rastérisation via `pypdfium2` (Apache-2.0/BSD-3), reconnaissance
  via le binaire CLI Tesseract en `subprocess` (isolation de process
  gratuite, jamais de `ProcessPoolExecutor`). `PyMuPDF` explicitement
  écarté (AGPL-3.0).
- Détail complet des correctifs et leur rationale : D-066 à D-087 dans
  `docs/journal-decisions.md`.

## Validation

- 388 tests réussis, 39 ignorés (jeu local `tests/samples_real/` non
  versionné).
- `ruff check`, `ruff format --check` et `mypy --strict` validés (aucune
  nouvelle catégorie d'erreur).
- Testé en conditions réelles sur des dossiers utilisateur (`~/Documents`,
  `~/Téléchargements`) — PDF administratifs/juridiques, présentations
  PowerPoint et ODP réelles, tableurs Excel avec cellules fusionnées.

## Installation Windows

1. Télécharger l'archive ci-dessus (et son `.sha256` pour vérification) —
   `CorpusOne` pour l'usage standard, `CorpusOne-OCR` si vous voulez l'OCR
   des PDF scannés sans installer Tesseract.
2. Extraire **le seul** `.exe` de l'archive vers un dossier de votre choix.
   Aucun autre fichier n'est requis : le runtime Python (et Tesseract, pour
   la variante OCR) est embarqué dans l'exe.
3. Lancer l'exe (double-clic). Aucun droit administrateur et aucune
   connexion réseau ne sont nécessaires.

Le binaire n'est pas signé : Windows SmartScreen peut afficher un
avertissement lors du premier lancement. Vérifiez l'empreinte SHA-256 avant
l'exécution.

## Limites de cette beta

- OCR : portée v1 limitée aux PDF (pas les fichiers image seuls, pas les
  images intégrées dans `.docx`/`.pptx`).
- `CorpusOne-OCR.exe` : premier build réel sur un runner Windows — signalez
  tout souci de lancement ou de reconnaissance.
- Quelques bugs de gravité moyenne restent non corrigés (SmartArt PPTX,
  annotations/champs de formulaire PDF, commentaires XLSX en lecture
  seule) — détail dans `docs/journal-avancement.md`.
